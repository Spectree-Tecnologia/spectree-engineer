# Spectree modular monolith

One deployable, many modules, each one a bounded context that could become a service tomorrow without a rewrite. These rules are what makes that true. Seven of them are enforced by `scripts/check-boundaries.mjs` (runs first in `npm test` and in CI), one by `npm run perf` and the e2e suite; the rest by the review. A rule you want to break is an ADR, never a comment.

| # | Rule | Why | Enforced by |
|---|---|---|---|
| 1 | **The core is pure.** `modules/<m>/src` imports no framework, no ORM, no HTTP, no other module. Only `@<ns>/shared` and plain libraries. | Business rules outlive frameworks. A module you can test with `node` alone is a module you can move. | script (rule 1, 2) |
| 2 | **Modules depend on data, never on code.** A cross-module reference is an id. Two modules importing each other's business code is a cycle, and a cycle is one module pretending to be two. | The module graph stays acyclic, so any module can be extracted or replaced on its own. | script (rule 1) |
| 3 | **The aggregate is the transaction.** What is inserted, changed and removed together lives in one aggregate under one root, with one repository per root. Child entities have no repository. | Consistency boundaries are explicit; locks and transactions follow the aggregate, not the table. | review |
| 4 | **CQRS: commands and queries are different things.** A command is a use case: `execute()` returns `Result<void>`, side effects only. A query is a direct read (`modules/<m>/src/<aggregate>/query/`), never a use case, never through the domain model. | Reads scale and change at a different rate than writes; a use case that returns data is both and does neither well. | script (rule 5) + review |
| 5 | **Rules live as close to the data as possible.** A rule about one value is in its Value Object; about several attributes of one entity, in the entity (`tryCreate`); across entities none owns, in a domain service. A use case is flow: it calls rules, it never re-implements them. | The invariant is enforced wherever the object is built, not only on the path someone remembered to validate. | review |
| 6 | **Errors are codes in a `Result`, never thrown, never translated.** `Result.fail('ACCOUNT_NAME_TAKEN')`; the frontend owns the message in each language. | The core has no locale, no HTTP status, no stack trace to leak; every caller handles failure the same way. | review |
| 7 | **Identity comes from the token, never from the body.** `userId` is read from the JWT by the controller and passed in; the token itself never enters a module. Every route is closed unless marked `@Public()`. | The module cannot be tricked into acting for someone else, and auth is one guard, not a convention. | `JwtGuard` as `APP_GUARD` + review |
| 8 | **Transactions are explicit.** A use case that touches more than one aggregate runs inside `TransactionManager.runInTransaction`, and repositories accept the `TransactionContext`. | No hidden implicit transactions; a partial write is impossible by construction, not by luck. | type system + review |
| 9 | **A route is thin.** `apps/<frontend>/src/app/**/<m>/page.tsx` imports the module's page component and nothing else; the screen lives in `apps/<frontend>/src/modules/<m>/{components,data,pages}`. | The frontend has the same module boundaries as the backend; moving a module moves its screens. | script (rule 4) |
| 10 | **Tests sit at the seam, outside `src/`.** `modules/<m>/test/<aggregate>/*.test.ts` exercises use cases and queries through `execute()` against an `InMemory<Aggregate>Repository`; the e2e covers the guard, the status mapping and the query budget only. | One seam catches most defects for the least coupling; the suite runs in seconds with no database. | script (rule 3) + review |
| 11 | **Capacity is a test: a query budget per use case and a p95 budget per route, both in CI.** The query budget gates every ready pull request; the p95 budget runs every night and on demand, where it reports and never fails the run, and gates the `pre-release` run before production. The e2e of a route wraps the request in `expectQueryBudget(prisma.client, K, ...)` (`apps/backend/test/query-budget.ts`); a list of N rows fits the same K as a list of one. Every route has a line in `perf.config.json`; `npm run perf` drives it at 20 connections for 10 s and fails CI when any response is not 2xx, when a new route is over its p95 budget on two measurements in a row, or when a route the base already had is over it and more than 1.25x slower than the base's code measured on the same machine in the same run. A route over budget that the base serves as slowly does not fail the change: it is a roadmap line. | "Scalable" is a number or it is an adjective. An N+1 dies in the e2e that first lists two rows, not in production; a route that got slower shows in the next night's run and fails the release that would ship it, and a slow runner fails nobody. | `npm run test:e2e` on every ready PR + `npm run perf` nightly (reports) and pre-release (gate) + review |
| 12 | **Every table has the same spine.** `id String @id @default(uuid()) @db.Uuid` (the `Id` value object only accepts UUIDs), `createdAt DateTime @default(now()) @db.Timestamptz`, `updatedAt DateTime @updatedAt @db.Timestamptz`, and `deletedAt DateTime? @db.Timestamptz` on aggregates that are soft-deleted (then every query filters `deletedAt: null`). Money is `Decimal @db.Decimal(19, 4)` in the column and a string in the DTO, never `Float`; time is UTC in the database and localized only on the screen. If the product has tenants, `tenantId` is a claim in the token and an indexed column on every table from the first migration, never added later. The app connects as `app_runtime`, a role that owns nothing (`npm run db:roles` after every migrate); migrations and seed run as the owner (`MIGRATION_DATABASE_URL`). An append-only table is one `REVOKE UPDATE, DELETE` line in `apps/backend/db/roles.sql`, not a trigger the app could disable. | The `Entity` base already carries these four fields; a table that disagrees with it breaks hydration. Conventions decided once are free; decided per aggregate they are the rewrite. A role that owns nothing cannot rewrite history, whatever the bug. | script (rule 6) + boot check (`PrismaService` refuses the owner in production) + review |
| 13 | **Modules talk through domain events, never through calls.** When a use case in module A must make module B react, A publishes a `DomainEvent` (`{ name, aggregateId, occurredAt, payload }`) through the `EventPublisher` port from `@<ns>/shared` after its transaction commits, and B subscribes to the event name in its own backend wiring (`apps/backend/src/modules/<b>/`), never in the core. The in-process `InMemoryEventBus` is the only implementation until an ADR says otherwise. | Rule 2 forbids the import; this is the door that stays open. A subscriber is a module that can be moved to a queue tomorrow without touching the publisher. | script (rule 1) + review |
| 14 | **Identity is a module, and the first item of every roadmap.** One module (`identity`) owns users, credentials and token issuance; the guard in `apps/backend/src/shared/auth` only validates. The token carries `sub`, `name`, `email` and `roles` (a string array, empty by default); `@Roles('admin')` on a route closes it to those roles, on top of the JWT. Whether login is a password of our own or an external provider, and whether there are tenants, is decided in the interview (gate 4), before the first migration. | Nothing can be tested end to end until someone issues a token, and nothing is harder to retrofit than claims the schema never planned for. | `JwtGuard` + review |
| 15 | **Nothing exists that the goal does not need.** New code answers a success criterion, a limit of the contract or one of these rules. Before creating, use what is there, in this order: this codebase, `@<ns>/shared`, the platform and the standard library, an installed dependency. No abstraction, option, config or "for later" code beyond what these rules require, and scaffold that no criterion exercises is removed before the commit. A deliberate shortcut carries the comment `shortcut: <the limit>, <when to upgrade>`. Never cut: validation at a trust boundary, error handling that prevents data loss, security, accessibility, anything a criterion asks for. | Every line is read, tested, reviewed and attacked. Code nobody asked for costs verification rounds and proves no criterion. | plan gate + review |
| 16 | **The aggregate is the folder, and a name says what a file is.** `modules/<m>/src/<aggregate>/{dto,model,provider,query,use-case}`; a use case that spans two aggregates of the module lives in `modules/<m>/src/app/`. Files are kebab-case with the suffix of their kind (`*.entity.ts`, `*.vo.ts`, `*.repository.ts`, `*.query.ts`, `*.use-case.ts`, `*.prisma.ts`, `*.controller.ts`, `*.schema.ts`); a class has no suffix (`User`, never `UserEntity`) and a use case is named as a verb (`AuthenticateUser`). | Whoever opens a module finds each thing where every other module keeps it, and where a plan puts code can be judged before the code exists. | plan gate + review |
| 17 | **An entity is built through `tryCreate` and never changed in place.** `tryCreate` returns a `Result` that combines the Value Objects; `create` is `tryCreate` plus `throwsIfFailed`; props are frozen and a change is a `cloneWith`; identity comes from `Id.create`; `toJSON()` returns the props. | An entity that exists is valid, and one that changed is a new value: no path builds or mutates it around its rules. | review |
| 18 | **A list is paged, and a page holds at most 50 rows.** A query that returns a list takes `page` and `pageSize`, and refuses or caps a `pageSize` above 50. | The query budget and the p95 of rule 11 hold only while the size of a response is bounded. | review |
| 19 | **A controller is thin.** It injects the concrete adapter, builds the use case by hand, calls a query directly, and maps the failure code of the `Result` to 400, 401, 404 or 500. No rule, no query logic. | The HTTP layer can be replaced without moving a rule, and the module is tested without it. | review |

## Layout

```
modules/<m>/src/<aggregate>/{dto,model,provider,use-case,query}   pure core
modules/<m>/src/app/                                               use cases that span two aggregates of the module
modules/<m>/test/<aggregate>/                                      seam tests + mock/
apps/backend/src/modules/<m>/                                      controller, <m>.prisma.ts, prisma/models/<m>.model.prisma
apps/<frontend>/src/modules/<m>/{components,data,pages}            screens
apps/<frontend>/src/app/(private)/<m>/page.tsx                     thin route
packages/shared                                                    Result, Entity, ValueObject, UseCase, repositories, TransactionManager, DomainEvent
```

Support modules (`identity` first) come before the core domain; breadth before depth.
