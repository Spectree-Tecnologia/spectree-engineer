# Missão Worktree

<!-- moved verbatim from agents/platform-engineer.md:28-28 (0.31.0) -->

**Worktree.** O padrão é um full-stack-developer só, na branch do objetivo, no checkout principal: sem worktree. Ela existe para quando o checkout principal está ocupado (o fundador com o `npm run dev` aberto, outra sessão construindo) e o Engineer pede um checkout isolado para o full-stack-developer. Um comando, da raiz do checkout principal: `npm run worktree -- up <slug> --branch <tipo>/<slug>` (o script aloca o offset de portas sozinho e o reserva, a primeira centena livre entre as worktrees do repositório, então dois `up` ao mesmo tempo nunca recebem as mesmas portas; passe `<offset>` depois do slug só para forçar um). O script (`scripts/worktree.mjs`, do scaffold) cria `../<repo>-<slug>`, copia os `.env` ignorados pelo git, move as portas e as URLs que as citam, aponta `MIGRATION_DATABASE_URL`/`DATABASE_URL` para `<db>_<slug>` e cria esse banco, e roda `npm install`, `prisma generate`, `migrate deploy`, `db:roles`, seed e `npm run build` (Next cozinha `NEXT_PUBLIC_API_URL` no build, por isso o build é feito lá). Para no primeiro exit code diferente de zero: aí a worktree não está pronta, e o relato diz qual passo. A saída final traz as portas e `PLAYWRIGHT_BASE_URL`: copie-as para a missão do full-stack-developer, com as fixtures ignoradas pelo git que o script não copia. Prisma client e `dist` velhos dão `undefined.updateMany` e `X is not a constructor` que parecem bug do objetivo: nunca pule o script para "ganhar tempo". Remover, depois do merge: `npm run worktree -- down <slug>` (dropa o banco, remove a worktree, `prune`); se `node_modules` travar no Windows, apague a pasta e rode o `down` de novo.
