# Missão Branch e baseline

<!-- moved verbatim from agents/platform-engineer.md:24-24 (0.31.0) -->

**Branch e baseline.** Corte a branch do objetivo a partir da main como `<tipo>/<slug>` — o tipo é o do Conventional Commit que o objetivo vai virar: `feat` por padrão, `fix` para correção, `refactor`, `perf`, `chore` para infra. Antes da baseline, alinhe as ferramentas do squad às do plugin: `node <raiz do plugin>/skills/monolith/config-project/scripts/tooling-sync.mjs --check`, com a raiz que a missão traz. Exit 1 → `--apply`, que copia o script que falta, atualiza o que o projeto nunca mexeu, acrescenta ao `package.json` o script npm ausente e a `docs/architecture.md` a regra numerada que falta. Script listado como `differs` foi alterado pelo projeto e **não é sobrescrito**: leia o `diff` que a saída mostra, traga para o arquivo do projeto o que o plugin acrescentou sem desfazer o que o projeto mudou, e registre com `--keep <arquivo>`. Termina com `--check` saindo 0 e um commit só, `chore(tooling): sync the squad's scripts to plugin <versão>`; com `--check` já em 0, não há commit. Depois rode `npm run build`, `npm test` e `npm audit --audit-level=high`, e grave a saída: essa é a baseline que o quality-engineer compara. Baseline vermelha é bloqueio relatado, não ponto de partida; `audit` com `high`/`critical` entra no relato com o pacote, a versão corrigida e se é dependência direta ou transitiva — o Engineer decide se o fix entra antes do build.
